## 研究：pgvector 讲解 + mewmo 向量检索现状核查
- **关键发现**：mewmo **当前未用 pgvector 原生能力**。向量存于 `contentEmbedding.embedding`（JSON 数组列），相似度在应用层算：`queryRelated`（ai-run-service.ts:197）`take:500` 拉行 → `cosine()` 逐行算 → sort → slice(20)；`relationCandidates`（:240）同理 `take:500`。**暴力全算 + 500 行上限，无索引，无 DB 下推**。
- pgvector 是什么：Postgres 扩展，加 `VECTOR(n)` 列类型 + 距离算子（`<=> ` 余弦 / `<->` L2 / `<#>` 内积）+ ANN 索引（hnsw / ivfflat）。Neon 已内置支持。
- 迁移改法：`CREATE EXTENSION vector` → `ALTER COLUMN embedding TYPE vector(768) USING embedding::vector(768)` → `CREATE INDEX ... USING hnsw (embedding vector_cosine_ops)` → 查询 `ORDER BY embedding <=> $1 LIMIT 20`。
- ⚠️ 坑：① `VECTOR(n)` 维度锁死，改 embedding 模型（768 Gemini / 1024 Jina v3 / 1536 OpenAI）必须全库重算；② HNSW 查询快、适合 mewmo 读多写少，IVFFlat 适合超大数据集。
- 结论：embedding 模型切换（env 改动）与 pgvector 迁移**可解耦**——前者现在就能做，后者等内容量近 500 上限或多用户时再做更划算。链路口：embed→pgvector `<=>` 召回 top-K→reranker 精排，标准 RAG 两段式。
- 已向用户用对比图（before=JS 算 / after=pgvector+HNSW）讲解，并给出 A(迁移方案)/B(spec)/C(先接 embedding) 三个下一步选项。
