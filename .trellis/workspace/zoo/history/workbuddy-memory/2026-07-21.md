## 向量数据库选型讨论（Qdrant vs pgvector）
- 用户主动了解 Qdrant（GitHub qdrant/qdrant，Rust 向量引擎，30k+ stars，Apache-2.0），并追问"为什么你的推荐和 Qdrant 没关系"。
- 修正结论：**mewmo 的 agent 记忆 / 多模态检索场景，Qdrant 是合理且前瞻的默认选项**，不应简单排后。
  - 理由：用户已有 VPS（宝塔+Docker）跑 ai-server/rss-worker，Qdrant 同机 Docker 起容器 = $0，抵消"多运维一个服务"的扣分；RSS 文章多模态（正文+标题+配图）未来要吃多向量/混合检索，这正是 Qdrant 强于 pgvector 的点。
  - pgvector 仅适合"复用 Neon、零新增服务、当前规模小、纯语义匹配"的省事路径。
- 决策分叉：检索是独立核心能力+要高级特性（多向量/混合/高并发/agent 记忆）→ Qdrant；否则 → pgvector。
- 注意：下次不要再因"省事"把 Qdrant 排后而惹用户反感——用户对该项目明确倾向/想用 Qdrant。
