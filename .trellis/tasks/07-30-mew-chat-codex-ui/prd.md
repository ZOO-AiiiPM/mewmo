# PRD: Mew 对话页 Codex 风格 UI 重构

## 背景

当前 `/mew` 首页与 AI 侧边栏的对话 UI 视觉粗糙，用户反馈"比较丑陋"，对标 OpenAI Codex 的对话界面重构。两个入口共用同一套渲染组件（AgentSidebar → TranscriptList → AssistantRow），改动一处两端生效。

## 用户痛点（原始反馈）

1. 整体设计丑陋，说不清具体哪里，但和 Codex 差距明显
2. 消息滚动区上下边缘没有虚化（渐隐）效果，内容生硬地被裁切
3. 历史会话展开面板很丑：一列"新会话"平铺，无信息量
4. 工具调用 UI 难看：全宽边框卡片堆叠；长时间调用没有任何进行中反馈
5. 回复的 Markdown 渲染效果差（字号过小、标题无层级、密度不对）

## 需求范围

### R1 消息区视觉重构（Codex 风格）
- 用户消息：右对齐小气泡（浅色底、圆角），不再全宽
- 助手消息：无边框无底色，直接排版在画布上，阅读密度舒适
- **正文字色用主色 `--ink`（暗色主题下为白色），不用灰色 `--ink-soft`**；次要信息（工具行、时间戳）才允许灰阶
- 消息区上下边缘用 CSS mask 渐隐，滚动时内容自然淡出
- 空会话 hero 与建议 chips 视觉同步微调（保持现有结构）

### R2 工具调用 UI 重做
- 从"全宽边框卡片"改为 Codex 式轻量行内状态行：小图标 + 单行文字，无边框
- 运行中：微光 shimmer 文字动画 + 实时耗时显示（如"正在搜索工作区 · 8s"）
- 完成后：弱化为浅灰色一行摘要，多个连续工具调用聚合折叠（默认收起，可展开查看每一步）
- 错误态保留可辨识的错误色

### R3 长时间调用反馈
- 工具运行超过阈值（3s）后显示计时；transcript 底部在 streaming 期间显示"正在工作…"状态行
- 无需后端改动（不新增心跳事件），纯前端计时

### R4 历史会话面板重设计
- 抽屉视觉重做：更窄的行高、hover 态、活跃项标记、显示相对更新时间
- 隐藏空会话（messageCount === 0 且非当前活跃）避免"新会话"刷屏
- 自动命名：首轮完成后，前端用首条用户消息截断（≤24 字符）调用已有 PATCH 重命名，仅当标题仍为"新会话"时执行

### R5 Markdown 渲染增强
- 修复解析缺口：水平线 `---`、嵌套列表缩进、删除线 `~~x~~`、任务列表 `- [ ]`
- 标题渲染为真实层级（h1–h3 映射为不同字号/字重，而非 strong）
- 提升整体字号与行高至可读水平（正文 ≥13px，代码块 ≥12px）
- 代码块、表格、引用、列表样式全面对齐 Codex 阅读体验
- 保留自研解析器 `parseSharedNoteMarkdown`，不引入第三方渲染库

### R6 侧边栏 Agent 面板容器同步打磨
- `mewmo-ai-rail` 头部、tab 切换、面板内边距与新消息区风格统一
- 侧边栏内的 transcript / 工具行 / 输入框与 /mew 完全一致（共用组件天然满足，容器样式需跟上）

## 非目标

- 不改后端流式协议（不加心跳/进度事件、不加服务端自动命名）
- 不改会话数据模型和 API 契约
- 不动"总结"tab、ConfirmationCard 业务逻辑
- 不做虚拟滚动等性能重构

## 验收标准

1. `/mew` 与侧边栏 Agent tab 双端视觉一致，明/暗两种主题下无样式回归；助手正文为主色而非灰色
2. 消息区滚动时顶部/底部有渐隐效果
3. 工具调用运行中可见 shimmer 动画与计时；连续多个完成的工具调用聚合为一行可展开
4. 助手回复的标题、列表、代码块、表格以正确层级和舒适字号渲染
5. 历史会话面板不再出现大量"新会话"；发过消息的会话自动获得截断标题
6. `pnpm lint`、`pnpm test:unit`、`pnpm build` 全绿
