# Agent 评测发现清单（① 采集阶段实时记录）

> 用户实测中持续追加。每条按「归因分类」拆分——只有 P（提示词）类进本任务的优化范围，其余拆给独立任务。

## 归因分类说明

- **P = 提示词可解**：改 system.zh.md / skill prompt 就能修
- **T = Agent 能力缺口**：缺 tool 或 tool 描述问题（agent 服务端代码）
- **F = 前端 bug**：web 端行为缺陷
- **U = UX 设计**：交互/视觉需要设计方案，非单点 bug

---

## 发现清单

### #1 没有日期 tool，不知道今天日期 `T` + `P`
- 现象：问今天日期/「最近一周的笔记」等时间相关任务时模型无法感知当前时间
- 拆分：
  - **P（速效）**：system prompt 组装时注入当前日期时间（服务端每轮动态拼入，成本极低）——先做这个
  - **T（可选）**：加 `get_current_time` tool；若 prompt 注入已够用则不必加
- 状态：待做

### #2 拼音输入法未隔离，composition 期间回车直接发送 `F`
- 现象：中文输入法拼音候选还没上屏，按回车确认候选词时消息被直接发出
- 拆分：Composer 的 keydown 处理缺 `isComposing` / `compositionstart/end` 判断，前端单点 bug，改动小
- 状态：待做（优先级高，中文用户基础体验）

### #3 缺对话复制 / 重试 / 重新编辑 `U`
- 现象：assistant 消息无复制按钮；失败或不满意时无法重试；用户消息无法重新编辑再发
- 参照：用户点名参照 liveagent 的消息操作交互
- 备注：重试功能后端已有 retry 链路（TranscriptList 有 onRetry，仅失败时暴露），需扩展为通用消息操作条
- 拆分：独立 UI 功能任务（消息 hover 操作条：复制/重试/编辑）
- 状态：待做

### #4 打开 agent 加载过程无过渡动画 `U`
- 现象：打开侧边栏/进入 /mew 时加载态生硬，无 skeleton/渐入
- 拆分：独立 UX polish 任务，与 #3 可合并为「Agent 对话体验打磨」
- 状态：待做

### #5 确认操作（proposal 卡片）体验差 `U` + `P`
- 现象（见截图 xwb3n21g-4d6159aa.png）：
  1. 确认交互「太呆」——卡片只有 mewmo + 「已完成」，信息量近乎为零
  2. 确认后没有文字说明当时确认的内容是什么（无法回溯这次写操作做了什么）
- 拆分：
  - **U**：proposal 卡片重设计——确认前展示 diff/摘要，确认后保留「做了什么」的记录（标题、变更摘要、目标位置）
  - **P**：确认执行完成后，assistant 的收尾文案应复述本次变更要点（这部分提示词可引导）
- 状态：待做

### #6 会话中也应展示笔记上下文 UI 芯片 `F/U`（已澄清）
- 用户澄清：希望**对话流里也附上笔记 UI 芯片**，表示当前会话建立在该笔记上下文之上（目前芯片只在输入框里，发送后消息不显示上下文标记）
- 拆分：前端展示——用户消息（或会话头部）渲染上下文芯片，复用输入框芯片样式；数据上 context 已随消息传递，主要是展示层补齐
- 状态：待做

### #7 删除笔记失败：确认时报「会话正在处理另一条消息」 `T`（bug，高优）
- 现象（截图 tnsfr6ok / xymbvjd0）：agent 出了「移入废纸篓」proposal，用户点确认 → 卡片变「失败：这个会话正在处理另一条消息，请稍后重试」
- 分析：assistant 回合看似已结束（已输出收尾文案），但服务端会话锁未释放，确认请求被并发拦截——会话状态机/锁释放时序 bug，与提示词无关
- 拆分：独立 bug 任务（agent 服务端 turn 状态机），需查锁释放与 proposal 确认的时序
- 状态：待做（高优：核心写操作链路被阻断）

### #8 上传文件功能未实现 `功能缺口`
- 现象：附件芯片显示「演示：文件不会上传」，入口已有但链路没做
- 拆分：产品 backlog（需要存储+解析+注入上下文全链路），不属于本评测范围
- 状态：记录在案

### #9 缺暂停对话、编辑输入功能 `U`
- 现象：生成中无法中断（stop）；已发消息无法编辑重发
- 拆分：并入 #3 的「消息操作条」任务（复制/重试/编辑/暂停）；暂停需要后端 abort 链路配合
- 状态：待做

### #10 工具执行完成后 loop 无后续 + 页面数据不刷新 `T` + `F`
- 现象（截图 4yma13u0）：「创建知识库」确认执行成功后：
  1. **T**：对话无后续——执行完没有新的 assistant 消息确认结果/引导下一步，agent turn loop 在 action 执行后直接终止
  2. **F**：左侧知识库列表不自动刷新，需手动刷新页面才看到新建的库（写操作成功后未 invalidate 前端缓存/未发刷新事件）
- 拆分：T 部分与 #5-P 同根（执行后闭环），但这里是 loop 机制问题不是文案问题；F 部分独立前端任务（action 执行成功→刷新对应列表）
- 状态：待做（高优：直接伤心智模型「干完活不吹哨」）

### #11 深度洞察移出输入框 + 建立 skill 结构 `U/T`（feature）
- 用户需求：
  1. 「深度洞察」按钮不放在输入框内部，而是放在输入框**上方**
  2. 建立 skill 结构（skill 栏/选择器），深度洞察作为其中一个 skill
  3. 用户点击 skill 后才出现对应提示词（按需激活，而非常驻）
- 现状基础：后端已有 skill 概念（prompt-loader 的 AgentSkillResource，deep-insight 已是 preset skill，含独立 prompt/模型/allowedTools），主要是前端交互结构化 + 选择态传参
- 拆分：独立 feature 任务（composer 上方 skill 栏），后端基本就绪
- 状态：待做
